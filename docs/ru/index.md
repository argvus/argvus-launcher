`argvus-launcher` предоставляет конфигурацию Rofi, темы и меню, которые ARGVUS использует для открытия вещей с клавиатуры. Он содержит:

- запуск приложений (`SUPER + D`);
- конфигурацию Rofi и темы, используемые каждым меню Rofi ARGVUS;
- переключатель проектов, выбор SSH и выбор сниппетов (`argvus projects`, `argvus ssh`, `argvus snippets`);
- менеджер SSH-ключей (`argvus keys`), который создает, отображает, загружает и удаляет пары ключей;
- менеджер GPG-ключей (`argvus gpg`), который отображает, создает и экспортирует ключи и настраивает pinentry-gtk для gpg-агента;
- выбор эмодзи, просмотр шпаргалок и меню калькулятора.

Горячие клавиши объявлены в `argvus-hyprland`. Этот пакет предоставляет команды и меню, лежащие за ними.

## Запуск приложений (`SUPER + D`)

`SUPER + D` запускает `argvus launcher`, который открывает Rofi в режиме `drun`. Он отображает установленные графические приложения с соответствующими записями рабочего стола, и выбранное приложение запускается при нажатии `Enter`.

1. Нажмите `SUPER + D`.
2. Введите часть имени приложения. Список отсортирован, а фильтр не учитывает регистр.
3. Нажмите `Enter`, чтобы запустить приложение, или `Esc`, чтобы закрыть меню.

```sh
argvus launcher                  # opens the application menu
argvus launcher --config PATH    # uses another Rofi configuration file
```
Любой другой аргумент передается `rofi`. `--config` без значения прекращает работу с ошибкой.

Hyprland запускает `argvus launcher --config <Rofi configuration>`, когда запускается программа по умолчанию `rofi`, которая является значением по умолчанию. Если значение по умолчанию `launcher` в стандартных приложениях установлено на другую программу, Hyprland запускает вместо этого `<program> --show drun`. Установите его в стандартных приложениях Центра управления, который сохраняет значение в `argvus-config`.

В списке отображаются только приложения с записью рабочего стола. Приложение, которое не устанавливает файл `.desktop`, не может быть найдено здесь.

## Конфигурация и темы Rofi

Пакет устанавливает конфигурацию Rofi под `/usr/share/argvus/launcher/config/`:

| Файл | Роль |
| --- | --- |
| `config.rasi` | Точка входа, используемая каждым меню ARGVUS. Настраивает Rofi `configuration` (шрифт, без иконок, отсортированный список, нечувствительное к регистру сопоставление) и импортирует `theme.rasi`. |
| `theme.rasi` | Цвета и разметка окна, панели ввода и списка. Импортирует одну тему и файл режима. |
| `mode.rasi` | Переопределение режима. В упакованном файле нет переопределений, и сохраняется тёмный режим. |
| `themes/<family>/theme.rasi` | Палитра семейства тем, например `argvus-dark` или `tokyo-night`. |
| `themes/<family>-spaced/theme.rasi` | Вариант с промежутками того же семейства. |

Пакет предоставляет 22 семейства, и каждое имеет вариант `-spaced`. Упакованный `theme.rasi` импортирует `argvus-dark`.

### Где находится активная конфигурация

ARGVUS разрешает каждый файл Rofi через `paths_config`. Первым побеждает существующий файл среди переопределений пользователя, копии пользователя, устаревших местоположений и сгенерированного дерева; в противном случае используется упакованный файл под `/usr/share/argvus/launcher/config/`. Копия файла пользователя находится в `$XDG_CONFIG_HOME/argvus/data/rofi/<file>`: префикс `launcher/config/` хранится под `rofi/`.

ARGVUS создает копию пользователя при первом изменении файла скриптом ARGVUS; `argvus-appearance` делает это для изменений темы, акцента и режима. Файлы, которые никогда не изменялись, продолжают читаться из пакета, а копия пользователя имеет приоритет над упакованным файлом.

Когда `argvus-session` применяет шрифт при запуске сессии, он переписывает строку `font:` из `config.rasi` с настройкой шрифта ARGVUS. Это изменение касается только копии пользователя. До появления этой копии используется упакованный файл, к которому пользователи не могут записывать, поэтому изменение шрифта вступает в силу после того, как первое изменение внешнего вида создало копию.

### Изменение темы

`argvus-appearance` управляет изменениями темы. Когда тема изменяется, она переписывает копии пользователя так, чтобы `config.rasi` указывал на новый `theme.rasi`, а `theme.rasi` импортировал палитру лаунчера сборки темы (`~/.config/argvus/data/generated/theme/current/launcher/theme.rasi`), которая имеет активное семейство, макет и выделяющий цвет. Без сборки темы она импортирует копию семейства, а макет Spaced выбирает вариант `-spaced` активного семейства. Элементы выбора темы, такие как меню темы и меню макета, читают тот же `config.rasi`, поэтому они также используют активный стиль.

Не редактируйте файлы под `/usr/share/argvus/launcher/`; они заменяются при обновлении пакета. Вносите изменения в копию пользователя, под `$XDG_CONFIG_HOME/argvus/data/rofi/`.

## Переключатель проектов (`SUPER + O`)

`argvus projects` (`SUPER + O`) перечисляет проекты, которые вы добавили, и открывает выбранный в отдельной рабочей области Hyprland, с `argvus terminal` в его каталоге. Если рабочая область проекта уже существует, переключатель просто фокусируется на ней.

Для доступа только с клавиатуры, `SUPER + ALT + 1` по `SUPER + ALT + 9` открывают проект в этой позиции списка без меню. Позиции — это номера, показанные в меню. Они следуют порядку списка, поэтому добавление или удаление проекта может изменить их. `argvus projects open <number or directory name>` делает то же самое из терминала, а неудачи отображаются в виде уведомления.

Эффективный список проектов ограничен 9, так как именно столько `SUPER + ALT + 1..9` может адресовать. `argvus projects add` (и страница "Проекты" в Центре управления, которая его вызывает) отказывается добавлять проект или корень, если это приведет к превышению общего количества до более чем 9, и сообщает об ошибке вместо этого.

Проект поступает из двух мест в разделе `projects` `argvus-config`:

- `paths`: отдельные каталоги проектов.
- `roots`: каталоги, непосредственные подкаталоги которых являются проектами. Корень, который не существует, игнорируется.

По умолчанию ни один корень или путь не настроен; добавьте хотя бы один, прежде чем `SUPER + O` сможет что-либо отображать.

Управляйте ими через терминал:

```sh
argvus projects add ~/Work/api          # one project
argvus projects add --root ~/Clients    # every subdirectory of ~/Clients
argvus projects remove ~/Work/api       # removes it from paths and roots
argvus projects list                    # prints the roots and paths
```
`argvus projects pick` показывает тот же список и выводит выбранный путь вместо его открытия. Другие инструменты могут использовать его, как `argvus git`. Отмена ничего не выводит.

Если корневой каталог или путь отсутствует, `SUPER + O` сообщает, что проекты не найдены. Необязательная команда редактора, `/projects/editor`, запускается в том же рабочем пространстве при его создании.

Записи считываются из текущей конфигурации; загрузчик не сохраняет их копию.

Открытие проекта также сохраняет его путь как активный проект для сессии, который блок телеметрии Dev Dashboard (`argvus widget-telemetry`) использует, чтобы сообщать о git проекта, прослушиваемых портах и контейнерах.

## SSH (`SUPER + ALT + S`)

`SUPER + ALT + S` открывает выбор с хостами, определёнными в `~/.ssh/config`. Выбранный хост открывается в новом терминале ARGVUS, запущенном `ssh <host>`, в текущем рабочем пространстве.

### Настройка

Добавьте запись `Host` для каждого сервера в `~/.ssh/config`:

```ini
Host myhost
    HostName myhost.local
    User boss
    IdentityFile ~/.ssh/myhost
    IdentitiesOnly yes
```
Сначала убедитесь, что `ssh myhost` работает в обычном терминале. Запуск осуществляется только через `ssh`; аутентификация, ключи и проверка хоста обрабатываются OpenSSH.

### Использование

1. Нажмите `SUPER + ALT + S`.
2. Введите часть имени хоста или используйте стрелки.
3. Нажмите `Enter`. Терминал откроется и запустит `ssh <host>`.

Когда сессия завершится, окно останется открытым и покажет статус выхода, например `ssh exited with status 0. Press Enter to close.`. Нажмите `Enter`, чтобы закрыть его. Это важно для сервисов, таких как GitHub, GitLab и Gitea: они аутентифицируют пользователя и сразу закрывают соединение, потому что не предоставляют оболочку. Окно сохраняет их сообщение на экране, вместо того чтобы исчезнуть.

### Правила

- Шаблонные записи (`Host *`, `Host *.internal`) являются блоками сопоставления, а не целями, и никогда не перечисляются.
- Каждый псевдоним в строке `Host` перечисляется отдельно (`Host a b` перечисляет `a` и `b`). Дубликаты удаляются.
- Хосты, определенные только в файлах, загруженных с помощью `Include`, не перечисляются; средство выбора читает только основной файл.
- Запускаются только псевдонимы, состоящие из букв, цифр, `.`, `-` и `_`. Любое другое имя отклоняется с уведомлением.
- Конфигурация принимает окончания строк Windows (CRLF).
- `ARGVUS_SSH_CONFIG` заменяет путь к файлу конфигурации, что полезно для тестирования.

### Команды

```sh
argvus ssh list          # prints the configured hosts, one per line
argvus ssh open myhost   # opens a specific host without the picker
```
### Устранение неполадок

| Симптом | Причина и решение |
| --- | --- |
| Уведомление "хосты не найдены в ~/.ssh/config" | Файл отсутствует или не содержит строк `Host`. Выполните `argvus ssh list` для проверки. |
| Хост отсутствует в списке выбора | Это шаблон, он берется из файла `Include` или содержит символы, не разрешенные набором. Добавьте его в основной файл с простым псевдонимом. |
| Окно сразу показывает статус ошибки | Выполните `ssh <host>` в обычном терминале, чтобы увидеть полное сообщение (недостижимый хост, неправильный ключ и т.д.). |
| Окно показывает `message.ssh_session_ended` вместо текста | Установленный пакет `argvus` старее этой версии. Обновите `argvus`. |

Требуются `openssh` и `argvus` (команда `argvus terminal`).

## SSH-ключи (`argvus keys`)

`argvus keys` управляет парами ключей в `~/.ssh` и ключами, удерживаемыми ssh-agent. У него нет ярлыка. Страница **SSH-ключи** в Центре управления (Приложения) использует те же команды.

```sh
argvus keys                              # shows the options and an example
argvus keys list                         # one pair per line: name, type, fingerprint, comment, passphrase, loaded
argvus keys generate NAME                # creates ~/.ssh/NAME as ed25519, without a passphrase
argvus keys generate NAME --type rsa     # RSA with 4096 bits
argvus keys generate NAME --comment C    # comment: letters, digits and . _ @ + -
argvus keys generate NAME --passphrase   # ssh-keygen asks for the passphrase in an ARGVUS terminal
argvus keys load NAME                    # adds the key to the agent; opens an ARGVUS terminal only if it has a passphrase
argvus keys unload NAME                  # removes the key from the agent
argvus keys unload-all                   # removes every key from the agent
argvus keys delete NAME                  # deletes both files; refused while the key is loaded
```
Правила, применимые к каждой команде:

- Имя ключа становится именем файла в `~/.ssh`, поэтому оно может содержать только буквы, цифры, точку, дефис и подчеркивание. Оно не может начинаться с точки и заканчиваться на `.pub`. Существующая пара никогда не перезаписывается.
- В списке отображаются только пары с публичным файлом (`NAME.pub`), и только их можно загружать, выгружать или удалять.
- Пароли никогда не передаются как аргументы команд, не записываются в журнал и не отображаются в Центре управления. `load` и `generate --passphrase` открывают терминал ARGVUS, а OpenSSH считывает секрет из этого терминала.
- `list` сообщает `unknown` в колонке `loaded`, когда агент недоступен. Он никогда не делает догадок.
- `delete` окончательно удаляет приватный ключ. Сохраните копию любого ключа, который вам еще нужен.
- `ARGVUS_SSH_DIR` заменяет `~/.ssh`, что полезно для тестирования.

Агент — это служба пользователя `argvus-ssh-agent.service`, запущенная `argvus-session`. `SSH_AUTH_SOCK` указывает на него в сессии.

Требуется `openssh` (`ssh-keygen` и `ssh-add`) и `argvus` (команда `argvus terminal`).

| Симптом | Причина и решение |
| --- | --- |
| `load` открывает терминал, но ключ не загружен | Введите парольную фразу в этот терминал. Если запрос не появился, запустите `ssh-add -l`, чтобы посмотреть, что держит агент. |
| Терминал показывает `Could not open a connection to your authentication agent` | Hyprland запустился раньше агента, поэтому в его терминалах отсутствует `SSH_AUTH_SOCK`. Запуск производного приложения возвращается к `$XDG_RUNTIME_DIR/ssh-agent.socket`, поэтому обновите `argvus-launcher` и откройте новый терминал. |
| `list` показывает `unknown` в колонке `loaded` | Агент недоступен. Проверьте `systemctl --user status argvus-ssh-agent.service` и переменную `SSH_AUTH_SOCK`. |
| `delete` сообщает, что ключ загружен | Сначала запустите `argvus keys unload NAME`, затем удалите его снова. |
| `generate` сообщает, что имя уже существует | Выберите другое имя. Существующие пары никогда не заменяются. |

## Ключи GPG (`argvus gpg`)

`argvus gpg` перечисляет, создает и экспортирует GPG-ключи и импортирует открытые ключи. gpg-agent всегда использует `pinentry-gtk`: ARGVUS записывает pinentry в `gpg-agent.conf` перед генерацией ключа. У него нет ярлыка. Страница **GPG keys** в Центре управления использует те же команды.

```sh
argvus gpg                                         # shows the options and an example
argvus gpg list                                    # one key per line: fingerprint, key id, type, expires, secret, validity, user ID
argvus gpg generate "Name <you@example.com>"       # RSA 4096 key, expires in 2 years, the pinentry asks for the passphrase
argvus gpg generate "Name <you@example.com>" --algo dsa --bits 2048 --expire 2031-06-30
argvus gpg generate "Name <you@example.com>" --expire 0                        # never expires
printf '%s\n' "$PASSPHRASE" | argvus gpg generate "Name <you@example.com>" --passphrase-stdin
argvus gpg generate "Name <you@example.com>" --no-passphrase --yes   # unprotected private key; --yes is required
argvus gpg export-public you@example.com ~/public.asc   # public key in ASCII armor, mode 600
argvus gpg export-public you@example.com ~/public.asc --force        # replaces an existing file
argvus gpg import ~/colleague.asc                  # imports public keys; private keys are refused
argvus gpg status                                  # gnupg installed, and the pinentry in use (argvus, user or default)
argvus gpg export-public you@example.com -          # prints the public key to standard output (used by the copy action)
argvus gpg export-private FINGERPRINT ~/private.asc --yes   # private key in ASCII armor, mode 600; --yes is required
argvus gpg import-private ~/private.asc            # imports a file that holds a private key
argvus gpg delete FINGERPRINT --yes               # deletes the key and its secret part; --yes is required
argvus gpg edit expire FINGERPRINT 2y              # new expiry for the key and each subkey (0, Nd/Nw/Nm/Ny or YYYY-MM-DD)
argvus gpg edit passwd FINGERPRINT                 # changes the passphrase; the pinentry asks for the old and the new one
argvus gpg edit sign FINGERPRINT SIGNER --yes     # certifies the key with the secret key of SIGNER
argvus gpg edit revoke FINGERPRINT --reason unused --yes   # revokes; reason none, compromised, superseded or unused
argvus gpg edit trust FINGERPRINT full            # trust none, marginal, full or ultimate
argvus gpg keyserver send FINGERPRINT --yes       # publishes the key to the keyserver set in gpg.conf
argvus gpg keyserver recv FINGERPRINT             # fetches the key from that keyserver
```
`generate` принимает следующие параметры:

- `--algo rsa|dsa` выбирает алгоритм ключа. По умолчанию используется `rsa`.
- `--bits` выбирает размер ключа. RSA принимает `1024`, `2048`, `3072` и `4096`, по умолчанию `4096`. DSA принимает `1024`, `2048` и `3072`, по умолчанию `2048`; gpg не может создавать более крупные ключи DSA, поэтому `4096` отклоняется до запуска gpg.
- `--expire` принимает `0` для отсутствия срока действия, число, за которым следует `d`, `w`, `m` или `y` (например, `2y`), или дату в формате ISO `YYYY-MM-DD`, которая должна быть реальной датой.
- `--passphrase-stdin` читает парольную фразу с первой строки стандартного ввода. Центр управления использует её. Пустая строка отклоняется.
- `--no-passphrase --yes` создаёт незащищённый ключ. Два режима парольной фразы нельзя комбинировать.

Каждый ключ получает один основной ключ для сертификации и подписи и один подчинённый ключ для шифрования, чтобы он мог шифровать файлы, а также подписывать коммиты и пакеты. Подчинённый ключ соответствует основному ключу: `rsa` того же размера для RSA и `elg` того же размера для DSA, что является парой, требуемой стандартом DSA.

Правила, применимые к каждой команде:

- Пароли никогда не передаются в виде аргументов командной строки, не записываются в журнал или не отображаются в Центре управления. С `--passphrase-stdin` пароль передаётся в gpg на файловый дескриптор 0 через пайп. Без этой опции gpg запрашивает окно pinentry, которое открывает `gpg-agent`.
- `--no-passphrase` хранит приватный ключ без защиты. Он отклоняется, если не указан `--yes`.
- `import` отклоняет любой файл, содержащий пакет секретного ключа, в ASCII или бинарном виде. Приватные ключи покидают связку ключей только через `export-private`, который требует `--yes` и использует режим записи `600`; `import-private` возвращает их обратно.
- Команды, которые изменяют или публикуют ключи (`export-private`, `delete`, `edit sign`, `edit revoke`, `keyserver send`), требуют `--yes`. Контрольный центр передает его только после собственного подтверждения. 
- Команды, использующие секретный ключ, запускают gpg с `--no-tty`, поэтому gpg никогда не пытается открыть терминал. Парольная фраза поступает из окна pinentry, за исключением `generate --passphrase-stdin`. 
- `generate` заставляет gpg-agent использовать `pinentry-gtk`. Она записывает эту строку между маркерами `# BEGIN argvus-managed pinentry` и `# END argvus-managed pinentry`, сохраняет остальную часть `gpg-agent.conf` и сохраняет предыдущий файл как `gpg-agent.conf.bak`. Когда блок уже указывает `pinentry-gtk`, файл и gpg-agent остаются без изменений. Команда отказывается выполняться, если `gpg-agent.conf` уже устанавливает `pinentry-program` вне этого блока, чтобы два значения никогда не конфликтовали.
- Установка пакета никогда не записывает в `~/.gnupg`. Изменения конфигурации происходят только при генерации ключа.
- `GNUPGHOME` заменяет `~/.gnupg`, что полезно для тестирования.

`gnupg` и `pinentry` являются обязательными зависимостями: команды работы с ключами требуют gpg, а окно ввода пароля - `pinentry-gtk`.

| Симптом | Причина и решение |
| --- | --- |
| `generate` не открывает окно ввода пароля | Проверьте `argvus gpg status`. `pinentry-gtk` должен быть установлен, а сессия должна предоставлять `WAYLAND_DISPLAY` или `DISPLAY`. |
| `generate` сообщает, что `pinentry-gtk` не установлен | Установите пакет `pinentry`. |
| `generate` сообщает о строке `pinentry-program` вне блока ARGVUS | Удалите эту строку из `~/.gnupg/gpg-agent.conf`, затем снова выполните команду. |
| `generate` сообщает, что размер ключа не поддерживается | Проверьте размер для алгоритма: DSA останавливается на 3072 битах. |
| `generate` сообщает, что подключение шифровального ключа не удалось | Ключ был создан. Добавьте подключение с помощью `gpg --quick-add-key FINGERPRINT cv25519 encr 2y` или удалите ключ с помощью `gpg --delete-secret-and-public-key` и создайте его снова. |
| `import` отклоняет файл | Файл содержит приватный ключ. Экспортируйте только публичный ключ на другой машине с помощью `argvus gpg export-public`. |
| `list` не показывает ключи | Связка ключей в `GNUPGHOME` (или `~/.gnupg`) пуста. Запустите `argvus gpg generate` для создания ключа. |

## Фрагменты (`SUPER + ALT + N`)

`SUPER + ALT + N` открывает выборщик с вашими фрагментами. Выбранный фрагмент вводится в фокусное окно на позиции курсора, без использования буфера обмена.

### Настройка

Добавьте фрагмент с именем и его текстом:

```sh
argvus snippets add "email" "you@example.com"
```
Проверьте, что это было сохранено:

```sh
argvus snippets list
```
Фрагменты хранятся в разделе `snippets` `argvus config` в виде записей `{name, content}`. Вы можете просматривать их с помощью `argvus config get /snippets/items`.

### Использование

1. Щелкните в текстовое поле приложения, которое должно получить текст.
2. Нажмите `SUPER + ALT + N`.
3. Выберите фрагмент по имени и нажмите `Enter`. Текст будет набран там, где находится курсор.

### Команды

```sh
argvus snippets add "NAME" "CONTENT"   # adds a snippet, or replaces the one with the same name
argvus snippets remove NAME            # removes a snippet
argvus snippets list                   # prints index and name, one per line
argvus snippets open NAME              # types a snippet by name
argvus snippets open 2                 # types the snippet at position 2 of `list`
argvus snippets                        # opens the picker (same as the shortcut)
argvus snippets --help                 # shows the options and an example
```
### Правила

- Имена уникальны и чувствительны к регистру. Добавление сниппета с уже существующим именем заменяет его содержимое.
- Содержимое не может быть пустым: пустой сниппет считается не найденным.
- `open` рассматривает имя, состоящее только из цифр, как позицию. Чтобы избежать неоднозначности, используйте имена с буквами, например, `code2`.
- Позиция относится к порядку, показанному `list`. Удаление сниппета сдвигает позиции следующих за ним.

### Устранение неполадок

| Симптом | Причина и решение |
| --- | --- |
| Уведомление "нет сниппетов" при нажатии горячей клавиши | Сниппет еще не добавлен. Сначала выполните `argvus snippets add`. |
| `open` сообщает, что сниппет не найден | Имя не совпадает точно. Сравните с `argvus snippets list`. |
| В приложении ничего не отображается | Активное окно не является текстовым полем, или это приложение X11, работающее под XWayland, которое может игнорировать такой ввод. Проверьте с применением нативного приложения Wayland. |

Требуются `wtype`, `rofi`, `jq` и `argvus` (команда `argvus config`).

`wtype` имитирует нажатия клавиш на уровне ввода Wayland. Некоторые приложения X11, работающие через XWayland, игнорируют эти события, поэтому текст может там не появляться, даже если фрагмент был найден.

## Git (`SUPER + ALT + G`)

`SUPER + ALT + G` открывает тот же выбор проекта, что и `SUPER + O`. Выбор проекта открывает `lazygit` (или `gitui`) непосредственно в нём, в новом терминале ARGVUS на текущем рабочем пространстве. Нет отдельного шага для предварительного выбора проекта.

### Настройка

Установите один из двух инструментов. Оба являются необязательными зависимостями этого пакета:

```sh
sudo pacman -S lazygit   # or: sudo pacman -S gitui
```
### Использование

1. Нажмите `SUPER + ALT + G`.
2. Выберите проект из списка или нажмите `Esc`, чтобы отменить. Отмена ничего не открывает.
3. Терминал открывается в директории проекта и запускает TUI.

Проект, который не является git-репозиторием, отображает уведомление и ничего не открывает. Чтобы пропустить выбор, передайте директорию:

```sh
argvus git ~/Projects/api
```
### Выбор инструмента

`argvus-git` использует `lazygit`, когда он установлен, и `gitui` в противном случае. Чтобы предпочесть `gitui`, установите `ARGVUS_GIT_TUI` для команды:

```sh
ARGVUS_GIT_TUI=gitui argvus git
```
Переменная считывается из окружения команды, которая запускает скрипт. Она не хранится в конфигурации ARGVUS.

### Устранение неполадок

| Симптом | Причина и решение |
| --- | --- |
| Уведомление "не репозиторий git" | Выбранный проект не является репозиторием git, или его директория была перемещена. Удалите или исправьте это с помощью `argvus projects remove`. |
| Уведомление "установите lazygit или gitui" | Ни один из инструментов не установлен на `PATH`. Установите один из них. |
| В выборщике нет проектов | Проект не был добавлен. Используйте `argvus projects add`. |

## Выбор эмоций (`SUPER + .`)

`SUPER + .` открывает `rofimoji` с конфигурацией ARGVUS Rofi. Найдите эмоцию по имени, нажмите `Enter`, и эмоция копируется в буфер обмена. Вставьте её с помощью `Ctrl + V` в нужное приложение.

Пока открыто окно выбора, сеанс игнорирует уведомления о раскладке клавиатуры, которые он обычно показывает. Лончер записывает краткоживущий маркер в каталог кеша ARGVUS и удаляет его примерно через одну секунду после закрытия окна выбора.

Требуются `rofimoji` и `wl-clipboard`.

## Калькулятор (`SUPER + C`)

`SUPER + C` открывает режим `calc` Rofi с конфигурацией ARGVUS Rofi. Введите выражение, и список результатов обновляется по мере ввода. Выберите результат, как определяет режим `rofi-calc`.

Пакет лончера предоставляет конфигурацию Rofi и зависит от `rofi-calc`. Сам ярлык объявлен `argvus-hyprland`.

## Шпаргалки (`SUPER + SHIFT + /` и `SUPER + CTRL + /`)

`cheatsheets.sh` показывает список ярлыков только для чтения в большом окне Rofi. Он принимает имя приложения в качестве аргумента:

```sh
cheatsheets.sh hypr     # Hyprland shortcuts (SUPER + SHIFT + /)
cheatsheets.sh kitty    # terminal shortcuts (SUPER + CTRL + /)
cheatsheets.sh <name>   # any other application with a cheatsheet
```

- `hypr` использует `data/generated/hypr/keybindings.txt` из конфигурации ARGVUS пользователя, если этот файл существует. В противном случае используется шпаргалка Hyprland, поставляемая с `argvus-hyprland`.
- `kitty` использует терминальную шпаргалку, поставляемую с `argvus`.
- Любое другое имя читает `<name>/docs/cheatsheets/<language>.txt`. Если этого файла нет, окно не открывается.

Язык — португальский, если системная локаль `pt-BR`, и английский в противном случае. `Esc` закрывает окно. Выбор строки только закрывает его; ничего не выполняется.

## Другие меню, использующие конфигурацию Rofi

Конфигурация лаунчера разделяется с компонентами, принадлежащими другим пакетам:

- История буфера обмена (`SUPER + H`) и её сочетание клавиш для очистки (`SUPER + SHIFT + H`) объявлены в `argvus-hyprland`. Они передают `cliphist` в Rofi с этой конфигурацией. `cliphist` берется из `argvus-session`, который запускает рекордер буфера обмена, заполняющий историю; мета-пакет `argvus` также от него зависит.
- Выбор темы, акцента и раскладки в `argvus-appearance` открывает Rofi с использованием `config.rasi`.
- Правила окон Hyprland распознают пространства имён `argvus-launcher` и `rofi`, поэтому меню получают обработку поверхности лаунчера.

## Упаковка и зависимости

Пакет `argvus-launcher` не зависит от архитектуры и устанавливает:

- `argvus launcher`, `argvus-snippets`, `argvus-ssh` и `argvus-git` в одной и той же директории;
- `/usr/share/argvus/launcher/config/` с конфигурацией Rofi и темами;
- `/usr/share/argvus/launcher/sh/` с `cheatsheets.sh` и `emoji-picker.sh`.

Необходимые зависимости: `argvus-session`, `argvus-appearance`, `argvus`, `bash`, `jq`, `hyprland`, `libnotify`, `rofi`, `rofi-calc`, `rofimoji`, `wl-clipboard`, `wtype`, `gnupg` и `pinentry` (который предоставляет `pinentry-gtk`). Необязательные зависимости: `openssh` для SSH-пикера и менеджера SSH-ключей; `lazygit` и `gitui` для git TUI.

Установка пакета не пишет в `$HOME`. Конфигурация пользователя создается при запуске сессии, как описано в [Конфигурация и темы Rofi](#where-the-active-configuration-lives)].

## Устранение неполадок

| Симптом | Причина и решение |
| --- | --- |
| `SUPER + D` ничего не открывает | Проверьте `argvus launcher` в терминале. Убедитесь, что `rofi` установлен и что конфигурация Rofi существует. |
| `SUPER + D` не отображает приложения | У приложений нет ярлыка рабочего стола. Показаны только приложения с файлом `.desktop`. |
| Меню используют старый шрифт | Строка `font:` перезаписывается при запуске сессии. Перезапустите сессию после изменения шрифта. |
| Изменение темы не влияет на меню Rofi | Проверьте, указывает ли пользовательская копия `config.rasi` в `$XDG_CONFIG_HOME/argvus/data/rofi/` по-прежнему на упакованную тему. Примените тему из `argvus-appearance` снова. |
| `SUPER + O` сообщает, что проекты не найдены | Не настроен корень или путь, либо директории больше не существуют. Запустите `argvus projects list`. |
| `SUPER + C` или выбор эмодзи не открывается | Установите `rofi-calc` или `rofimoji` (требуются обе зависимости). |
| Cheatsheet не открывается | Файл с этим именем и языком не существует. Проверьте пути, описанные в разделе Cheatsheets. |
| `SUPER + H` ничего не показывает | История пуста или регистратор буфера обмена `argvus-session` еще ничего не сохранил. |

## Связанные компоненты

| Компонент | Ответственность |
| --- | --- |
| `argvus-hyprland` | Определяет горячие клавиши и правила окна Hyprland для меню. |
| `argvus-appearance` | Изменяет активную тему, акцент и раскладку, а также переписывает ссылки на тему Rofi. |
| `argvus` (`argvus config`) | Хранит проекты, фрагменты и настройку запуска по умолчанию. |
| `argvus-session` | Копирует начальную конфигурацию Rofi и устанавливает её шрифт при запуске сессии. |
| `argvus` (`argvus terminal`) | Открывает SSH-сессии, терминалы проектов и запросы пароля `argvus keys`. |
| `argvus` (`argvus widget-telemetry`) | Считывает активный проект, записанный `argvus projects`. |
| `argvus` (`argvus i18n`) | Предоставляет переведённые сообщения, используемые скриптами запуска. |
| `argvus` (`argvus control-center`) | Редактирует список проектов через `argvus projects`. |
